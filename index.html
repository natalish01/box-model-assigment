CSS Box Model — როგორ ითვლის ბრაუზერი ზომებს?

Box Model არის CSS-ის ფუნდამენტი. მისი სწორი გაგება გეხმარებათ აირიდოთ გაფუჭებული განლაგება (Broken Layout) და ზუსტად აკონტროლოთ ელემენტების ზომები.

Box Model-ის 4 შრე

margin
border
padding
content
Content
შიგთავსი: ტექსტი, სურათი ან სხვა HTML ელემენტები.
Padding
შიდა სივრცე კონტენტსა და ჩარჩოს (Border) შორის. იღებს ელემენტის ფონს (background).
Border
საზღვარი, რომელიც გარს ერტყმის Padding-ს. აქვს სისქე, სტილი და ფერი.
Margin
გარე გამჭვირვალე სივრცე, რომელიც ამ ელემენტს აშორებს მეზობელი ელემენტებისგან.

დიდი დუელი: Content-Box vs Border-Box

ორივე ბარათს ერთნაირი CSS აქვს: width: 300px; padding: 20px; border: 5px solid. ერთადერთი განსხვავება box-sizing-ია.

ბარათი A

box-sizing: content-box (ბრაუზერის დეფოლტი)

width: 300px ეხება მხოლოდ კონტენტს. padding და border ზემოდან ემატება, ამიტომ რეალური სიგანე ეკრანზე 350px გახდა: 300 + 20×2 + 5×2.

საბოლოო ზომა = Width + Padding + Border

ბარათი B

box-sizing: border-box

width: 300px მოიცავს კონტენტს, padding-სა და border-ს ერთად. ისინი მითითებული სიგანის შიგნით „ჩაიფუთა“ და ბარათი ზუსტად 300px დარჩა.

საბოლოო ზომა = Width (300px)

რატომ ტყდება განლაგება?

ორი სვეტი, თითოეული width: 50%, padding: 20px და border: 2px solid-ით. კონტეინერი ორივე შემთხვევაში ერთი და იგივეა.

ქეისი 1: content-box

თითო სვეტი 50% + 44px გახდა. ჯამი 100%-ს აჭარბებს და მეორე სვეტი ქვემოთ ვარდება.

შეჯამება და ოქროს წესი

თანამედროვე ვებდეველოპმენტში layout-ის პრობლემების თავიდან ასაცილებლად CSS პროექტს ყოველთვის ვიწყებთ ამ წესით:

*, *::before, *::after { box-sizing: border-box; }

რატომ გვიმარტივებს ეს წესი ცხოვრებას?
ის აიძულებს ყველა ელემენტს იმოქმედოს პროგნოზირებადად: თუ ელემენტს მიანიჭებთ width: 400px-ს, ის ეკრანზე მართლაც 400px დარჩება, მიუხედავად იმისა, თუ რამდენ Padding-ს ან Border-ს დაუმატებთ.
